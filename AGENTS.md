# FocusBuddy project instructions

1. Implement only the milestone explicitly requested by the user. Stop when that milestone is complete.
2. Inspect relevant existing files before editing them.
3. Do not rewrite working features or upgrade dependencies unnecessarily.
4. Put visible text in `strings.xml`. Put shared colours, dimensions, and styles in shared Android resources.
5. Do not invent YouTube accessibility identifiers or claim detection works without observed evidence.
6. Run appropriate build checks when available. Clearly distinguish compilation, automated tests, and actual device testing.
7. After implementation, report:
   - files changed and why;
   - checks run and their results;
   - numbered phone test steps with expected outcomes;
   - known limitations;
   - a suggested Git commit message.
8. Explain the main new concept in a short beginner-friendly paragraph.
9. Do not commit, push, reset, broadly delete files, or discard the user's changes unless explicitly requested.
10. Stop after the current milestone.
